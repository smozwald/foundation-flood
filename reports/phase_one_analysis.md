## TL;DR

Phase 1 produced two Random Forest models on a single zone (`000099_initial`, Chenab) under Leave-One-Event-Out (LOEO) CV:

- **Pixel-level classifier** (binary `is_flooded`): LOEO AUC = **0.991**
- **Field-level magnitude regressor** (% of field flooded): LOEO R² = **−0.275**, RMSE = **40.7 pp**
- **Pixel→field aggregation** (average pixel prob to field): R² = **0.041**

The field-magnitude conclusion ("doesn't work, go external") **holds up**. The pixel-ranking conclusion **does not hold up as stated** — the real AUC is far higher than the brief claims, and that high number is most likely **leakage**, not skill.

## Models trained

**Model A — Pixel-level RandomForestClassifier**
- Target: binary `is_flooded` per pixel per event.
- Config: 200 trees, max_depth=8, min_samples_leaf=10, class_weight='balanced'.
- Outputs averaged up to FoTW field level → field flood-% prediction (the pixel→field path).

**Model B — Field-level RandomForestRegressor**
- Target: continuous % of pixels in a FoTW field labelled flooded, per event.
- Config: 200 trees, max_depth=6, min_samples_leaf=5.
- Features: per-field aggregates of pixel terrain stats.

**Validation:** Leave-One-Event-Out (LOEO) for both — each fold withholds one event entirely.

## Why the 0.991 pixel AUC is a red flag, not a result

- The model covers **one zone**: 6,233 pixels × 10 events.
- LOEO withholds an **event**, but every pixel **location** still appears in 9 of 10 training folds.
- The classifier can therefore memorise each pixel's average flood propensity (topographic position) rather than generalise to a genuinely unseen location.
- An AUC of 0.991 under spatially overlapping folds is the signature of **location/label leakage**, not predictive skill. Terrain features such as `dist_to_channel_m` likely encode the Otsu mask boundary directly.
- Ironically, the brief's stated 0.6–0.75 would have been the *believable* result.

**Implication:** Before Phase 2 builds a disaggregation layer on top of "pixel vulnerability rank", pixel ranking must be re-validated with a **location-disjoint split** (leave-one-zone-out, or spatially blocked CV). The current evidence does **not** establish that pixel ranking generalises.

## Caveats / red flags

1. **Pixel AUC 0.991 ≈ leakage**, not generalisation (see above). Single most important caveat.
2. **Field model is data-starved**: ~370 covered fields × 10 events, LOEO leaving ~370 test rows per fold against a 9-feature, 200-tree regressor. R² < 0 is unsurprising.
3. **No independent flood-label validation**: JRC GSW comparison failed (data ends 2021); Copernicus EMS shapefiles never uploaded. The Otsu-derived labels are unchecked against ground truth.
4. **Notebook ≠ PDF** feature sets and the model cells were never executed in the committed version.
5. **"Drop constant features" is unverified** — soil_moisture/precip were low-importance, not shown to be constant. A zero-variance check (already a Phase 2 guardrail) should decide this, not assumption.
6. **"Ceiling ~0.15"** has no basis in any output.
7. **FoTW coverage 1.4–1.5%** is real and brutal — the field-level dataset is extremely sparse, which is itself a strong argument for the Phase 2 switch to fields + external magnitude.

## What this means for Phase 2

**Holds up:**
- Field-level *magnitude* regression fails → source Y% (area flooded) externally. ✅
- `discharge_ts` not needed as a model input. ✅
- Keep `ndvi_premonsoon`. ✅

**Needs correction before building on it:**
- "Pixel ranking works" rests on a leaky 0.991. Re-validate pixel/field **ranking** with a location-disjoint split before the disaggregation architecture depends on it.
- Run the zero-variance check (a stated guardrail) before dropping `soil_moisture` / `precip_premonsoon` — do not drop on assumption.
- Field-level *ranking* AUC is genuinely untested — test it by aggregating existing pixel scores to field level (no retraining) as the brief proposes.
